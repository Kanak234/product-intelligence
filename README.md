# Product Intelligence — prototype

Turns a loose product description into structured, validated catalogue data,
and shows where every single value came from.

Runs as one Python process. No Docker, no database, no model server, no
network. That is not a limitation of the prototype — the enrichment engine is
deterministic by design, and the language model in the full platform is an
optional gap-filler that can never overwrite a value found in the source text.

---

## Run it locally

```bash
pip install -r requirements.txt
streamlit run streamlit_app.py
```

Opens on <http://localhost:8501>.

## The browser frontend

```bash
pip install -r requirements-platform.txt
uvicorn pi_platform.api:app --reload
```

Then open <http://localhost:8000> — the API serves the page at `/` and the API
docs at `/docs`. No build step and no CDN; the page is one HTML file.

This is an alternative to the Streamlit UI, not a replacement: it talks to the
API over HTTP, so it needs the API running. Streamlit calls the engine directly
in-process, which is why that one still works with nothing else installed.

## Run it in Docker

```bash
docker compose up --build                       # app only
docker compose --profile data up --build        # + Postgres and Redis
docker compose --profile full up --build        # + API, worker, vector search
docker compose --profile llm  up --build        # + the local language model
docker compose --profile test run --rm test     # run the suite in-container
```

Profiles bring the stack up one stage at a time — see [`DOCKER.md`](DOCKER.md).
The app runs at every stage and degrades to stateless when a service is absent.

Streamlit Community Cloud does not read the `Dockerfile`; it installs
`requirements.txt`, so the cloud deployment below is unaffected.

## Deploy it

Push this folder to a GitHub repository, then on
[share.streamlit.io](https://share.streamlit.io) choose **New app**, point it at
the repo, and set the main file to `streamlit_app.py`. Nothing else to
configure — `requirements.txt` and `.streamlit/config.toml` are already here.

## What it does

**Single product.** Type or paste a product line. The engine extracts
specifications with regular expressions and unit conversion, classifies it
against a built-in taxonomy, derives values that were never stated (torque from
power and speed, current from power and voltage), validates the result against
20 rules, and writes an explanation of its own reasoning.

**Catalogue file.** Upload CSV, TSV, JSON, JSONL, HTML, TXT, Markdown, PDF or
Excel. Every record goes through the same pipeline, plus a cross-record
consistency check. Export the enriched catalogue as CSV or JSON.

## Provenance

The colour on every specification is the point of the product. Each value
carries a tag saying how it was obtained, and values can only be overwritten by
a more trustworthy source, never a less trustworthy one:

| Tag | Meaning | Trust ceiling |
|---|---|---|
| From source | Supplied verbatim by the source system | 1.00 |
| Read from text | Deterministic parser hit on the source text | 0.95 |
| Computed | Derived from other fields | 0.85 |
| Rule matched | Rule-based classifier | 0.80 |
| Model inferred | Generated by a language model | 0.65 |
| Category default | Category fallback, weakest evidence | 0.30 |

The **Traceable to source** figure on each record is the share of
specifications that came from the first three rows — the ones a buyer can check
against a datasheet.

## Tests

```bash
pip install -r requirements-dev.txt
pytest tests/ -v
```

358 tests with every service running; 179 with none, the rest skipping cleanly.
No external service is required to run the suite:

- `tests/test_product_intelligence.py` — the engine: extraction, units,
  taxonomy, validation, explanation, ingestion, and the accuracy thresholds
  measured against `data/eval/` (category accuracy ≥ 0.90, spec F1 ≥ 0.90,
  hallucination rate ≤ 0.05).
- `tests/test_app_core.py` — input parsing, pipeline invocation, provenance
  accounting, export.
- `tests/test_ui.py` — drives the real Streamlit app headlessly: renders it,
  fills the form, presses the button, checks what appears.
- `tests/test_llm.py` — the local model layer, against a stub server that
  deliberately lies, proving the engine rejects values that contradict the
  source.
- `tests/test_persistence.py`, `test_cache.py`, `test_vector.py`,
  `test_service.py`, `test_api.py`, `test_worker.py` — the platform layer.
  These skip when the optional dependencies or services are absent.

For the full stack:

```bash
pip install -r requirements-platform.txt
```

## Layout

```
streamlit_app.py          UI and styling only
app_core.py               logic the UI calls; no Streamlit imports, fully tested
product_intelligence/     the engine, unchanged from the platform backend
data/eval/                ground truth and adversarial sets for the accuracy tests
tests/
```

`app_core.py` holds no presentation and `streamlit_app.py` holds no logic, which
is why the UI can be tested at all.
